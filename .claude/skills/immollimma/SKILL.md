# immollimma — порядок работы

Ты сочиняешь музыку кодом и исполняешь её настоящими оркестровыми семплами. Ты **не слышишь** результат:
твои уши — приборы (`report.md`) и вкус заказчика (`taste.md`). Цель — хорошая пьеса **с минимумом вопросов**.

## 0. Среда (каждая новая сессия)

```sh
git clone --depth 1 https://github.com/Ranatar/immollimma && cd immollimma   # если ещё нет
sh tools/setup.sh            # ≈ 5–10 мин: библиотеки в libs/, пакеты, проверка libsfizz
python3 -m kit check         # всё «ok» — можно работать
```
Пока идёт клон библиотек (долго), читай `taste.md`, бриф и пиши план — не жди.

## 1. Прочитать

1. `taste.md` — **всегда, первым.** Правила оттуда применяются без вопросов; гипотезы — проверяются.
2. Заказ: `requests/<имя>/brief.json` (+ `cues.json`), либо вложения беседы, либо просто слова
   пользователя. Если брифа нет — составь его сам из слов (`schemas/brief.schema.json`) и сохрани в
   `requests/<имя>/brief.json`.
3. Карточки стилей из брифа: `kit/styles/<id>.json` (если пусто — `plan.py` подберёт по словам; проверь).
4. Перед работой с частями комплекта, которые трогаешь впервые: `docs/pitfalls.md`.

## 2. Спрашивать или решать

**Решай сам и пиши в плане, что решил**, если: поле брифа пустое (у него есть умолчание); выбор
обратим дешёвой пересборкой (тональность, темп, ведущий тембр, фактура); ответ есть в `taste.md`.

**Спроси (одним сообщением, все вопросы сразу, с вариантами)** только если:
- бриф противоречит сам себе (реклама + инструменты только Sonatina; длительность ≠ меткам на минуты);
- музыка к видео, а ни меток, ни видео нет и `sync.mode` не `none`;
- стиль из слабых мест библиотек (`fit.weak` карточки: романтическая кантилена, трейлерная эпика) —
  предупреди и спроси, принимает ли он компромисс или другой стиль;
- нужна чужая мелодия, которая может быть охраняемой.

`iteration.ask_before_full = false` (умолчание): эскиз и полная версия — **в одном заходе**, без ожидания.

## 3. План

```sh
python3 -m kit plan requests/<имя>      # → plan.md, plan.json
```
Прочти `plan.md`, поправь `plan.json` руками, где автоматика ошиблась (ведущие тембры не из стиля,
неудачные разделы). Таблица контрастов **обязательна** (урок первой редакции Р.С.Ф.Г.Р. в taste.md):
у соседних разделов различаются ≥ 3 из 5: ведущий тембр, фактура, регистр, пульс, динамика.
Добавь в план **хотя бы один сквозной процесс** (что медленно меняется на всю длину) и, если есть
персонажи, **лейтмотивы и их трансформации**.

## 4. Партитура

`requests/<имя>/piece.py` с `build(ctx) → Piece` (образцы: `examples/chorale_prelude` — барокко и ноты;
`examples/nocturne` — краски, смешанные библиотеки; `examples/phase` — процесс; `examples/rsfgr` —
к видео по меткам, гротеск, все приёмы обработки). API — `docs/guide.md`.

Правила:
- Высота — звучащая MIDI; `vel` — характер (слой и тембр), `gain` — уровень.
- Все времена — из `ctx.cues` / `ctx.plan` (метки), не на глаз. Удар — ровно на метку; `swell` — нарастание
  **к** метке; `silence` — действительно тишина (и хвост реверберации учти: обрывай за 1–2 с до).
- Случайность — только `c.rng` / `p.rng`.
- Не повторяй материал без изменения дольше 20–30 с: переоркестровка, регистр, гармония, плотность.
- Избегай частотных штампов (i–VI–III–VII, андалузская каденция, «хоррор = тремоло + кластер» как
  единственный приём), если их не просили.
- Темы пользователя (`themes`) — используй их, не выдумывай свои вместо.
- Метки разделов — `p.mark(t, "название")` (видны в отчёте и в партитуре).

## 5. Эскиз → проверка → полная версия

```sh
python3 -m kit run requests/<имя>/piece.py --sketch     # первые sketch_seconds
python3 -m kit run requests/<имя>/piece.py              # целиком
```
После каждого рендера **прочти `out/report.md` и посмотри `out/report.png`** (Read). Обязательно исправить:
провалы (gaps), перегруз, щелчки, `missing`, ноты далеко за записанным диапазоном. Если `flat stretches`
не задуманы — добавь контраст. Сравни novelty-пики с метками: музыка должна меняться там, где задумано.
Подозрительно тихо почти всё — ищи одно событие на 20+ дБ громче (docs/pitfalls.md).

Длинная пьеса: правь кусками `--from S --to S` (рендер окна), полную собирай в конце.

## 6. Отдать

Пользователю (SendUserFile): `out/audio.mp3` (+ видео: `python3 -m kit mux out/audio.mp3 видео.mp4 out/video.mp4`
если есть видео), `out/score.pdf`, `out/report.png` по просьбе; в сообщении — 2–4 строки: что сделано,
где решения по умолчанию, что проверено приборами, какие места самые рискованные (честно: «я не слышал»).

В репозиторий (коммит, см. §8): `requests/<имя>/{brief.json,cues.json,plan.md,plan.json,piece.py}`,
`requests/<имя>/out/{report.md,report.png,score.pdf,score.mid,credits.txt,render.json}`. Звук (`*.wav/*.mp3`)
в git не кладётся (.gitignore) — он уходит в беседу.

правило в «Правила». Свои догадки о причинах — только в «Гипотезы». Коммит.

- Инструмента нет в реестре — добавь в `kit/instruments.py` (имя SFZ-файла — из `libs/`), затем

- Приём нужен не раз — вынеси в `kit/devices.py` с описанием; новый стиль — карточка в `kit/styles/` и
  строка в `kit/styles/index.json`.

- После правок ядра: `sh tools/selftest.sh`.
